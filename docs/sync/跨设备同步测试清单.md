# 跨设备同步测试清单

> 用于验收 2.5.1 的同步修复。**两台设备**（Mac + Windows，同一 B 站账号）对照执行。
> 数据流与设计见 [`docs/ideas/004-本地歌单云同步.md`](../ideas/004-本地歌单云同步.md)。

## 开测前

- [ ] 两台都装/跑**修复版**（2.5.1+）。旧版 2.5.0 只推不拉，测什么都不准。
- [ ] 服务端已部署带 `/watch`、写前历史、全量删除闸门的版本。
- [ ] 记下测试前的云端状态，出问题好对照：

```bash
ssh root@8.163.0.99 "cd /data/biu-sync/27597762 && for f in favorites fav-items tags; do node -e 'const j=require(\"fs\").readFileSync(process.argv[1]+\".json\",\"utf8\");const d=JSON.parse(j);const e=Object.values(d.data);console.log(process.argv[1],\"v\"+d.version,\"活\",e.filter(x=>!x.__deleted).length,\"墓碑\",e.filter(x=>x.__deleted).length)' \$f; done"
```

**出任何问题先做这一步再排查**（保住现场）：

```bash
ssh root@8.163.0.99 "cp -a /data/biu-sync /root/biu-sync-databak/manual-\$(date +%Y%m%d-%H%M%S)"
```

关键路径速查：

| 东西 | Mac | Windows |
|---|---|---|
| 歌单三个 json | `~/Documents/Biu/` | `%USERPROFILE%\Documents\Biu\` |
| 启动快照（10 份）| `~/Library/Application Support/Biu/data-backups/` | `%APPDATA%\biu\data-backups\` |
| 同步记账 / 滚动备份 | 同上目录的 `playlist-sync-meta.json` / `playlist-sync-backups.json` | 同左 |
| 服务端数据 + 历史 | `/data/biu-sync/{mid}/`、`{mid}/history/` | — |

> dev 版（`pnpm dev`）的 userData 目录是 `biu-dev` 而不是 `Biu`，别找错。

## A. 实时性

### A1. 双向实时更新速度 ✅ 你列的第 1 条

- [ ] 两台都打开应用、都已登录，停在歌单页
- [ ] Mac 收藏 1 首 → 掐表看 Windows 多久出现
- [ ] Windows 收藏 1 首 → 掐表看 Mac 多久出现

**预期**：**约 0.8s**（发送端防抖 400ms + 推送 + 通知 + 拉取渲染）。超过 2s 说明接收端还在走防抖，或通知通道没连上。

### A2. 连续快速操作不卡住 ⚠️ 本次重点修复

- [ ] Mac 上**快速连续**收藏 6 首（间隔明显小于 400ms，就是手速点）
- [ ] 观察 Windows：应该**分批陆续到达**，不是长时间没反应后一次性全来

**预期**：连续操作期间每 ~1.2s 推一批，全部到齐不超过操作结束后 ~1.5s。
**这是原 bug 现场**：旧版会一直不同步，停手很久后 6 首一起出现。

### A3. 挂机后仍然实时

- [ ] 两台都开着，**放置 2 分钟以上不操作**（跨过服务端 25s 挂起上限好几轮）
- [ ] 然后 Mac 改一次

**预期**：Windows 仍在 ~0.8s 内更新。若变慢或不动，说明通知通道断了没重连。

### A4. 休眠唤醒后恢复

- [ ] Windows 合盖/睡眠 5 分钟 → 唤醒
- [ ] 唤醒后先不点应用窗口，在 Mac 上改一次，看 Windows 是否更新
- [ ] 若没更新，点一下 Windows 应用窗口（触发 focus），应立刻补齐

**预期**：最差也应在点窗口后立刻同步（focus 兜底）。

## B. 登录态

### B1. 退出登录 → 另一端改动 → 重新登录 ✅ 你列的第 2 条

- [ ] Windows 退出登录
- [ ] Mac 收藏 2 首、新建 1 个歌单夹、给 1 首打个标签
- [ ] Windows 重新登录

**预期**：登录后**立刻**（不用重启）拉到 Mac 的全部改动。登录触发 `syncNow()`，第一次 `/watch` 会立刻返回。

### B2. 应用关闭期间的改动

- [ ] Windows **完全退出**应用（不是最小化）
- [ ] Mac 收藏 2 首
- [ ] 重新启动 Windows 应用

**预期**：启动后自动拉到那 2 首。

### B3. 离线改动不丢

- [ ] Windows **断网**，收藏 2 首，然后**直接关掉应用**（不给它同步的机会）
- [ ] 恢复网络，重新打开 Windows 应用

**预期**：那 2 首会被推上云并出现在 Mac 上。本地落盘和同步是两条独立的路，关应用只丢"还没发出去的推送"，不丢数据。

## C. 并发与冲突

### C1. 两端同时改**不同**条目

- [ ] 断开 Windows 网络 → 两端各自收藏不同的歌 → 恢复网络

**预期**：两边的歌**都在**，谁也没覆盖谁（条目级合并）。

### C2. 两端同时改**同一**条目

- [ ] 断开 Windows 网络 → 两端给**同一首歌**打不同标签 → 恢复网络

**预期**：**较晚那次生效**（last-write-wins），不报错、不丢整批数据。

### C3. 一端删、一端改同一条

- [ ] 断开 Windows 网络 → Mac 删掉某首歌，Windows 给同一首改标签 → 恢复网络

**预期**：按时间戳裁决，两端最终**一致**（不会一台有一台没有）。

## D. 删除（本次新增闸门，重点验证不误伤）

### D1. 删单条

- [ ] Mac 从歌单里删 1 首

**预期**：Windows 同步删除。

### D2. 删一个歌单夹（多夹中的一个）

- [ ] Mac 有多个歌单，删掉其中一个（里面有歌）

**预期**：Windows 同步删除，其他歌单不受影响。

### D3. 删光唯一歌单 ⚠️ 曾被误拦

- [ ] 造一个只有 1 个歌单、里面 ≥5 首歌的状态，整个删掉

**预期**：**能同步出去**，Windows 也删掉。
**曾经的 bug**：服务端把这批操作当成"删光全部活条目"拒绝（409），导致这台设备之后每次同步都被拒、彻底卡死。现在客户端会带 `allowFullDelete` 确认。

验证服务端没拒绝：

```bash
ssh root@8.163.0.99 "pm2 logs biu-sync-server --lines 50 --nostream | grep -i '拒绝\|wipe_guard'"
```

**应该没有输出**。有输出就是误拦了。

## E. 数据安全（回归，别信"应该没事"）

### E1. 冷启动竞态不再清空数据 🔴 原事故复现

- [ ] 在**歌单数据较大**的那台上，反复冷启动应用 5 次以上（每次完全退出再打开）
- [ ] 每次启动后检查歌单夹、歌曲、标签是否完好
- [ ] 检查云端有没有莫名其妙多出墓碑（用开测前那条命令对比）

**预期**：数据始终完好，云端墓碑数不增长。
**这是 2.5.0 数据丢失的直接触发条件**——冷启动时 store 还没读盘完，同步就把空状态当"全部删除"推上云。

顺便看日志里有没有闸门被触发：

```bash
# Windows
type %APPDATA%\biu\logs\main.log | findstr /C:"拒绝推送" /C:"世代号"
```

### E2. 备份份数都是 10

- [ ] 反复启动应用 12 次以上
- [ ] 数 `data-backups/` 目录：应保留 **10 个**，最旧的被删

```bash
ssh root@8.163.0.99 "ls /data/biu-sync/27597762/history/ | wc -l; ls /data/biu-sync/27597762/history/ | head -3"
```

**预期**：每个 store 最多 10 份历史（三个 store 合计最多 30 个文件）。

### E3. 还原工具可用

- [ ] 跑一次预览（**不加 `--apply` 不会改任何文件**）

```bash
node dev_tools/restore-local-playlist.mjs
```

**预期**：列出滚动备份 + 首次迁移快照，条目数和实际歌单对得上。

## F. 异常与降级

### F1. 服务端挂掉时应用仍可用

- [ ] 停服务：`ssh root@8.163.0.99 "pm2 stop biu-sync-server"`
- [ ] 在应用里正常收藏、删除、建歌单
- [ ] 恢复：`ssh root@8.163.0.99 "pm2 start biu-sync-server"`

**预期**：断开期间应用**完全可用**（本地是 source of truth），不弹错、不卡 UI；服务恢复后改动自动补推上去（重连退避 2s→5s→15s→30s，最多等 30s）。

### F2. 断网重连

- [ ] 拔网线/关 WiFi 30 秒再恢复
- [ ] 恢复后在另一台改一次

**预期**：恢复后能重新收到通知，不需要重启应用。
