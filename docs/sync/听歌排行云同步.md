# 听歌排行云同步

## 用户行为

- 登录同一 B 站账号：桌面与网页读取同一云端排行；「最近一周」按滚动七天计算，总次数独立累计。
- 新播放先进入当前账号的本机待同步队列；收到云端确认后才移除。榜单不把本机待同步数冒充云端总数。
- 旧 `play-counts` 没有账号归属：登录后第一次同步时自动、原子地归入当时登录的账号队列，无需手动操作。原始旧 store 不改写；归入后本机未归属记录清空，重复同步、切换账号均不重复导入。多个账号共用一台设备时，旧记录归第一个登录的账号。
- 未登录的新播放先留本机，下次登录时自动归入该账号。登录后的记录始终归播放发生时的账号，切换账号不转移队列。
- 本地文件可同步排行元数据，不同步音频文件或本机封面。旧身份键若含文件路径，发送前转为确定性摘要；没有承诺不同路径的同一音频会自动合并。

## 数据链路与边界

`recordPlayCount` → 平台 `rankingLocal` 原子读改写 → `pushRankingEvents` → `/api/play-ranking` → 单进程互斥写盘 → 返回云端快照与确认序号 → 清除已确认的本机队列。

- Electron：固定 IPC `store:ranking-local`，主进程串行完成读取、修改和落盘；失败向渲染层传播。保存于应用用户目录的 `play-ranking-sync.json`，不进入可同步的歌单目录。
- Web：同源 `/__biu_sync/play-ranking`，复用服务端会话换取 JWT；浏览器不接触 B 站 Cookie 或同步 JWT。本机队列和云端缓存保存在 IndexedDB，一个 readwrite 事务防止多页签覆盖。
- Android / iOS：同一平台能力通过 Preferences 串行持久化，不是空实现；本次仅验证适配层，未真机验收。
- 服务端：`{mid}/play-counts.json` 保留每首总次数、近 30 天时间明细和每台设备的最高已确认序号；沿用原子 rename、写前历史和单进程部署限制。
- 新接口只追加、读取，不支持删除。`/sync/play-counts` 仍返回 404，不让排行进入歌单的覆盖或墓碑路径。
- 复用 `/watch` 的 `play-counts` 版本通知。已同步版本的回声直接跳过，不新增长轮询、心跳或周期探测。
- 普通播放计数口径沿用「切到这首歌记一次」，不是听满若干秒；补齐分 P、暂停、刷新封面不再次计数。旧历史缺分 P 时不猜测所属分 P，保留旧身份以避免误合并。

## 协议

`GET /api/play-ranking` 返回 `{ mid, version, updatedAt, records }`。`records` 的 `totalCount` 为总次数，`recentPlays` 为 epoch 毫秒；不向客户端返回其他设备的序号表。

`POST /api/play-ranking` 接收：

```json
{
  "expectedMid": "42",
  "deviceId": "11111111-1111-4111-8111-111111111111",
  "events": [
    {
      "seq": 1,
      "record": {
        "key": "online:BV1234567890:12",
        "title": "示例歌曲",
        "totalCount": 1,
        "recentPlays": [1792641600000]
      }
    }
  ]
}
```

一批最多 100 条，客户端同时按 1 MB 拆批；单条历史时间明细超过 10000 条时拆成连续事件，合计次数和时间明细都保留。返回快照附 `ackSeq`。已经确认的序号再次上报只返回原结果，不累计、不提升版本；序号缺口拒绝整批。账号以 JWT 为准，`expectedMid` 只是防止登录态变化后把旧批次交给另一个账号，不能指定要写入的任意账号。

## 提示与恢复

| 画面 | 含义 | 用户操作 |
| --- | --- | --- |
| 未登录 · 仅本机记录 | 没有云端归属 | 登录后按需确认合并 |
| 云端排行 · N 次待同步 | 排行来自云端，另有本机队列 | 等待本次同步完成 |
| 云端排行 · 已同步 | 已取得该账号云端结果 | 正常使用 |
| 同步失败 · 显示上次云端结果 | 有缓存，失败后已停自动请求 | 阅读原因，恢复后重新打开排行页或重新登录，自动继续 |
| 同步失败 · 尚未读取云端排行 | 还没有可展示的云端快照 | 不把空列表当成云端无记录 |
| 云端尚未启用听歌排行 | 同步服务或 Web BFF 尚未升级 | 先部署服务端，再刷新 / 更新客户端 |
| 本次听歌记录保存失败 | 本机落盘失败，没有宣称已保存 | 检查设备存储；不向云端发送未可靠保存的记录 |

429 / 5xx 后不自动重试；新播放仍落盘，回到前台或通知回声也不穿透失败暂停。重新打开排行页、重新打开应用或重新登录才重新尝试。应用关闭后，已经完成落盘的队列保持；未收到确认的批次重发也不重复累计。

## 发布与回退

1. 备份同步服务的用户数据目录，部署 `biu-sync-server`，保持单进程 fork；验证新增端点鉴权和无缓存响应。
2. 部署 Web BFF 与 Web 渲染产物，固定白名单新增 `/__biu_sync/play-ranking`；旧客户端和原有歌单接口继续可用。
3. 更新桌面客户端；用同一测试账号做两端播放、旧记录确认、断网恢复与账号切换验收后再确认上线。

2026-10-22 已完成同步服务与 Web 的生产发布：Chrome 实际播放、另一窗口自动更新、桌面协议公网读取和服务器落盘结果一致。桌面程序升级与打包客户端实机验收尚未执行；旧客户端不会因为只更新服务器就自动获得上报能力。

代码回退不删除云端 `play-counts.json`、历史备份或客户端 `play-ranking-sync` 数据。恢复旧云端快照可能导致序号缺口，应先核对历史和本机队列，禁止自动重置设备号以绕过去重。
