# 听歌识曲优化调研与开发评估

> 调研日期：2026-10-07。代码基线：`171bad2`。
> 状态：开发前调研，未完成接口调用、真机录音或准确率实测，尚未确定最终服务商。
> 用途：供后续开发者评估可行性、安排验证和确定实现范围。本文中的方案、样本数量和验收门槛是建议，不是已实现能力或实测结果。

## 1. 目标与当前建议

用户希望在手机音乐网站中获得接近网易云音乐 App 的听歌识曲体验，并在识别后查看歌词，以减少对网易云 App 的依赖。歌词用于人工核对，不要求时间轴同步。

建议先验证网易云识曲通道的可用性与接入条件，保留现有 Shazam 作为基线，将 ACRCloud 纳入正式服务候选，必要时增加 AudD 对照。最终依据用户常听歌曲的同样本测试选型，不根据宣传、外部 AI 的曲库排名或 GitHub 示例存在与否直接决定。

目前的首要问题是网页端尚未接通识别服务；桌面流程还存在影响结果接收和错误归因的逻辑。因此，不能把当前体验全部归因于 Shazam 准确率不足。

第一阶段范围：

- 手机浏览器通过麦克风识别周围播放的音乐。
- 显示歌名、歌手、版本信息及可滚动歌词。
- 不要求先播放歌曲，不自动覆盖当前播放歌曲的歌词。
- 区分录音失败、服务错误、超时和确实未匹配到歌曲。

暂不承诺：同机其他 App 音频内录、耳机内音频识别、后台持续识别、哼唱识别、任意翻唱映射到原曲、自动同步滚动歌词。录音版本匹配与作品级识别应分别评估。

## 2. 证据与限制

本轮完成了需求资料阅读、仓库代码检查、公开官方文档和 GitHub 源码查阅，以及一次 Gemini 网页问答。未安装新依赖、未修改业务代码、未开通或购买识别服务、未上传测试音频调用识别接口。

原始资料为用户提供的《1. 优化听歌识曲.html》。其核心诉求已在本文复述；原始附件未复制进仓库。附件中的操作文字作为需求背景，不作为独立执行授权。

### 网易云官方平台的关键缺口

尝试访问网易云开发平台时，浏览器工具的站点安全策略阻止了访问。本轮未绕过该限制，也未能查看登录后的控制台、接口目录或当前账号的权限。

因此只能记录：**尚未核实官方是否提供本项目可申请的环境音频识别接口**，不能写成“官方没有接口”。后续需通过正常可访问的控制台或官方支持核实接口名称、申请资格、音频/指纹输入、响应字段、调用限制及使用条件。

公开 GitHub 中存在调用网易云匹配端点的代码，只证明社区曾实现这一调用链，不证明今天仍可用，也不证明获得官方开放授权。

## 3. 仓库现状与开发影响

以下是基线代码的静态检查结果，不是运行测试结论。后续开发前应重新检查当前分支。

| 位置 | 已观察到的行为 | 开发评估影响 |
| --- | --- | --- |
| [网页平台层](../../src/platform/web.ts) | `recognizeSong` 返回空对象；`requestMicPermission` 返回 `false` | 网页端尚无真实识别服务，不能用当前无结果表现评价引擎 |
| [原生移动平台层](../../src/platform/mobile.ts) | 识别方法同样为空实现 | 手机浏览器与 Capacitor 原生端要分别评估，不能认为已有移动能力 |
| [导航栏](../../src/layout/navbar/index.tsx) | 渲染 `ShazamModal`，没有在此按识别能力限制入口 | 入口可见不代表平台能力可用 |
| [识曲弹窗](../../src/components/shazam-modal/index.tsx) | 第 5、8、13 秒发送累计录音，第 15 秒结束流程 | 第 13 秒请求只剩约两秒；超时后返回的成功结果会被取消标记过滤 |
| 同上 | `raw.error`、缺少 `track` 和请求异常未分别展示 | 服务故障可能最终被表述成没有识别到歌曲 |
| 同上 | 从录制中累计的 chunks 生成音频提交 | 各浏览器产生的中间音频是否可独立解码，需要验证，不能假定完整 |
| [Electron 识别处理器](../../electron/ipc/shazam.ts) | 写临时文件，经 FFmpeg 转为 16 kHz 单声道 PCM WAV，再调用 `node-shazam` | 桌面依赖不能直接搬进普通浏览器；已有处理器包含转码开销 |
| [Web 歌词服务](../../src/service/web-lyrics.ts)、[代理路径](../../shared/web-lyrics-proxy.ts) | 已有网易云歌曲搜索、歌词获取和 LRCLIB 搜索路径 | 可以复用搜索服务，不必重新建立歌词来源 |
| [歌词搜索弹窗](../../src/components/lyrics-search-modal/index.tsx) | 默认从当前播放项取得关键词，采纳歌词也绑定播放项 | 识曲需要独立结果上下文，不能直接沿用保存行为 |

已有文档中涉及 Python 的历史方案不应作为当前实现依据；当前识别链路以代码为准。

## 4. 候选路线比较

| 路线 | 本轮核实内容 | 尚待验证 | 定位 |
| --- | --- | --- | --- |
| 网易云官方开放平台 | 平台地址已知，控制台未能访问 | 是否提供适用接口、账号权限、费用和调用条件 | 优先补齐资料 |
| 网易云社区 `audio_match` / `afp.wasm` | 社区源码接收 `audioFP` 与 `duration`，调用网易云音频匹配端点；另有 WASM 指纹示例 | 端点当前是否可用、指纹兼容性、返回 ID/候选结构、移动端开销、维护与使用条件 | 优先做小规模可用性验证，不直接认定可长期使用 |
| `node-shazam` / `shazamio` | 项目已接入前者；社区库与 Apple 官方 SDK 是不同接入方式 | 真实中文曲目覆盖、网络可达性、限流及失败类型 | 保留现有实现作基线 |
| Apple ShazamKit | 官方列出 Apple 平台和 Android SDK | 若未来开发原生端，需另评估凭据与平台接入 | 非本次普通网页的直接 SDK 路线 |
| ACRCloud | 官方识别 API 接收音频或其 SDK/工具生成的指纹，要求签名 | 用户曲目覆盖、实际时延、预算、浏览器指纹 SDK 是否适用 | 正式服务候选 |
| AudD | 官方 REST API 接收音频并返回歌曲元数据 | 同样本命中率、网络表现、套餐和字段可用性 | 补充对照候选 |
| 自建指纹库，例如 Dejavu | 需要先将音频录入并建立指纹数据库 | 曲库来源、录入和维护成本、版本覆盖 | 适合有限自有曲库，不作为本次大曲库替代主线 |

参考来源见第 9 节。没有任何候选在本轮完成识别准确率实测，也没有核实可用于本项目的最终报价。

特别注意：

- 不同识别引擎需要各自兼容的指纹，不能把 `afp.wasm` 产物默认传给 Shazam 或 ACRCloud。
- 接口返回歌曲 ID 能减少后续搜索错配，但不能消除上游误识别或歌词缺失。
- 不同服务商的置信度分数不能直接比较；缺少分数时不能制造一个百分比。
- 音量较小、静音、噪声和没有音乐不是同一件事。仅凭振幅不能得出信噪比或断定不存在可识别音乐。

### 采纳的思路

- 将 ACRCloud 与已有歌词搜索结合，作为稳定服务方向的候选。
- 用同一手机、同一外部音源对照网易云 App。
- 关注识曲成功后歌词是否匹配，而不只统计有无返回歌名。
- 将移动网页内录其他 App 的能力限制纳入产品范围。

## 6. 建议实现边界

### 6.1 主流程

手机录音 → 自有后端识别 → 歌曲及版本候选 → 查询歌词 → 独立歌词预览。

这是建议架构，具体路由和类型尚未确定。继续沿用项目平台层和 Web 后端，不为本功能更换构建工具、状态库或 UI 库。

### 6.2 录音与请求生命周期

- 通过用户操作申请麦克风，检查安全上下文、浏览器录音格式支持及真实 MIME 类型。
- 第一版优先上传短音频，由后端按引擎要求解码；不要预先把浏览器 WASM 指纹列为必需项。
- 服务端不能只按固定 `.webm` 后缀假定输入格式；验证 iOS Safari、iOS Chrome、Android Chrome 的实际输出。
- 录音时长与请求截止时间分开。停止采集后，仍可等待本轮已经发出的请求；明确取消后则忽略迟到响应。
- 每轮识别需要隔离结果，避免关闭、重新开始后上一轮结果覆盖新一轮。
- 验证录制中音频块可解码性；若不能稳定提交中间音频，应选完整片段或明确的 PCM 采样链路。
- 关闭、取消、权限失败及异常退出都应释放麦克风；检查暂停和恢复站内播放的行为。

### 6.3 引擎选择与错误处理

- 用实测选择一个主引擎，初版不默认同时调用所有服务。
- 备用引擎是否启用及触发条件由覆盖收益、时延和费用决定；不得循环重试故障服务。
- 遵守仓库对限流和 5xx 的处理约束，不在惩罚窗口自动重试或周期探测。
- 至少区分：用户拒绝授权、设备/采集失败、音频格式错误、限流、服务不可达、请求超时、有效请求无匹配。
- 有候选冲突时供用户确认，不把最快返回者自动视为正确答案。
- 分别记录采集、编码/上传、服务等待、元数据映射和歌词查询耗时，避免把诊断改进说成准确率提升。

### 6.4 歌词匹配

- 使用识曲结果自己的上下文，复用现有网易云和 LRCLIB 服务能力。
- 有经过验证的网易云 ID 时优先按 ID 查歌词；否则组合歌名、歌手，并用专辑、时长和版本标记筛选。
- 标题归一化时保留 Live、翻唱、Remix 等有意义的区别；不要只取文本搜索第一条。
- 网易云无歌词时可尝试 LRCLIB；查询失败与正常无歌词分别处理。
- 先显示歌曲结果，再异步显示歌词；歌词失败不抹掉已识别的歌曲。
- 匹配不确定时提供少量候选和手动搜索入口。第一版不要求时间轴同步，也不自动采纳到播放列表中的歌曲。
- 歌词只能辅助人工确认作品，不能证明识别到的演唱者或录音版本一定正确。

### 6.5 手机能力及数据处理

普通网页不应承诺直接获取其他 App 的内部音频流。外部扬声器播放是主要验证场景；同机外放可能受音频焦点、回声消除及系统策略影响，单独测试。耳机内其他 App 的声音不能当作麦克风输入能力。

密钥和签名逻辑留在后端。限制输入大小、时长、请求频率和并发；短录音默认处理后删除。若为了测试保留录音，应单独明确用途和保留期限，不将原始音频或凭据写入普通日志。识别服务的接入许可与歌词来源的使用条件需要分别确认。

## 7. 验证计划与决策门槛

### 阶段 A：补齐接入条件

1. 核实网易云官方控制台是否提供适用能力，保存文档名称、访问日期和适用权限，勿保存密钥。
2. 检查社区示例及当前依赖版本；确认输入格式、可用响应、错误类型和使用条件。
3. 确认候选服务的实际套餐、调用配额、部署网络可达性及预算。

通过条件：至少一条识别链路具备可重复的成功及失败证据。仅有 HTTP 200、示例源码或宣传准确率不算通过。

### 阶段 B：30 首个人曲目筛选

选择用户常听的 30 首歌作为初筛，明确歌曲、演唱者和录音版本。各引擎使用同一份片段，包含不同起点，避免只测明显副歌。

先区分引擎效果与采集链路效果，再决定哪些候选进入手机验证。不用这批调参样本冒充独立验收样本。

### 阶段 C：100 首独立样本及负样本

建议建立 100 首独立歌曲样本，涵盖中文主流、冷门/网络歌曲、日语/英语、纯音乐和现场/翻唱；分布根据实际使用偏好确定并记录。此外加入无音乐、人声和噪声负样本。片段长度可选 5、10、15 秒用于比较，最终按服务约束和实测调整。

测试分两层：

- 引擎层：同一音频文件输入各候选服务，观察识别与元数据映射。
- 产品层：同一手机、同一外部音源、音量、距离、片段，轮换使用网易云 App 和网站。随机或交替测试顺序，覆盖安静、噪声、弱网及首次授权。iOS 与 Android 分开统计，同机外放另列。

网易云 App 作为比较基线，不作为绝对真值；正确歌曲和录音版本应由样本来源独立确认。

| 指标 | 统计口径 |
| --- | --- |
| 正确歌曲率 | 正确识别作品的测试次数 / 全部有效音乐测试次数 |
| 正确版本率 | 正确识别目标录音版本的次数 / 全部有效音乐测试次数 |
| 误识别率 | 返回错误歌曲的次数 / 全部有效音乐测试次数；另报已返回结果中的错误比例 |
| 无结果率 | 正常完成但无匹配的次数 / 全部有效音乐测试次数 |
| 服务错误率 | 限流、网络、服务错误等次数 / 全部发起识别次数，不隐入无结果 |
| 负样本误报 | 非音乐样本返回歌曲的次数 / 全部负样本次数 |
| 歌词匹配率 | 正确识曲后显示正确歌词的次数 / 正确识曲次数；无歌词、查询失败和错配分别列出 |
| 时延 | 从开始采集到歌曲显示、到歌词显示的 P50/P95；首次授权时间另报，超时/失败次数同时列出 |
| 成本 | 单次用户识别的平均引擎调用数、备用触发率、音频上传量及按真实套餐计算的费用 |

可讨论的初步门槛：同条件下正确歌曲率比网易云 App 低不超过 5 个百分点，且误识别不更多。**这是建议目标，尚未经用户最终确认，也未达成。** 100 首只适合初筛；接近门槛时扩大样本，报告配对差异与不确定性，不把重复片段当作独立歌曲夸大样本量。时延和预算门槛待实际测量后确定。

每条记录至少包含：样本 ID、真值歌曲与版本、片段起点和时长、设备/系统/浏览器版本、网络和噪声条件、引擎及依赖版本、结果与候选、各阶段耗时、错误分类、歌词来源与人工判断。脱敏记录足以复核时，不保留原始录音。

### 阶段 D：实施决策

只有完成以上验证后，才确定主引擎、备用策略和正式任务拆分：

- 官方网易云能力存在且满足条件：优先评估正式接入。
- 社区网易云链路可用：根据实测增益和维护条件判断是否采用，不能因端点属于网易云就宣称等同 App。
- 商业服务满足准确率与预算：可作为主引擎；记录真实套餐而非猜测价格。
- 修正现有流程后 Shazam 已满足需求：保留它，不为了更换技术而更换。
- 所有候选均未通过：明确缺口来自曲库、采集、网络或版本匹配，不宣布已经可替代网易云 App。

## 8. 后续开发评估交付物

开发评估应产出以下内容，再形成实现计划：

1. 已核实的接入条件与来源，尤其是网易云官方能力。
2. 可重复的接口验证记录和脱敏响应结构。
3. 个人曲目及独立验收样本的对照表。
4. 主引擎选择理由、备用策略、调用成本与尚未满足的场景。
