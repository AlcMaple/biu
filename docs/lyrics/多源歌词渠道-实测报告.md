## 结论

**三种渠道均已实际跑通搜索、匹配歌曲、获取歌词及格式检查。** 中文、日文、英文各选一首，每个渠道 3 首，共 9 次完整取词/解析检查通过。本轮 27 个平台请求，每个探测步骤仅发一次，没有自动重试或登录账号；没有启动常驻服务或下载音频。

| --- | --- | --- | --- |

| 酷狗 | 3/3 | 可解码的逐字 KRC | 可提供词级时间轴候选，保留来源版本并继续检查当前录音匹配 |
| AMLL | 3/3 | 含词级时间标记的 TTML | 可提供社区逐字歌词候选；数据接入和解析器代码许可继续分开处理 |

测试歌曲为《晴天》/周杰伦、《アイドル》/YOASOBI、《Shape of You》/Ed Sheeran。只代表这 3 首在本轮条件下的结果，不是全曲库覆盖率、稳定性或速度排名。

## 各渠道的成功路径与接入条件

### QQ

- 按固定版本 MIT 上游的匿名轻量搜索协议查询，获得 songmid 后，再调用普通歌词端点。三首的网关、搜索业务码与取词业务码均为成功值；LRC 解码后均存在有效行时间戳。
- 使用的是匿名协议标记 tmeLoginType=-1，不是用户登录 Cookie；没有读取浏览器或项目账号凭据。
- 本轮普通歌词端点对三首的 trans 字段均为空，因此这条路径只确认了正文，未确认译文或原生 QRC。
- 匿名搜索的实现选择与版本有关；本轮用固定上游已定义的 search_type=7。接入时需固定并验证协议，不能只沿用历史请求。

### 酷狗

成功路径是：**曲库搜索 → 核对歌手/版本、取得 FileHash 与秒制时长 → 用 Hash 与毫秒制时长查歌词候选 → 下载 KRC → 检查文件头并解码、解压 → 读取词级时段。**《アイドル》的歌词候选名称为 Idol，按同一歌手及标题别名匹配。

首次简化请求虽 HTTP 200，正文却是 0 字节。按上游请求层补齐请求形态后，只带关键词又得到业务 status=404、候选为空。取得歌曲 Hash/时长并走完整链路后，三首均得到业务成功与可解码 KRC。

这是成功链路的验证，不是逐参数的因果隔离实验；不据此断言所有歌曲一律必须某一个字段。接入时需要保留客户端参数、请求头、签名与业务码判断，不把 HTTP 200 或空正文当作“有歌词”。

### AMLL

- 官方公开检索端点返回歌曲元数据与文件 ID，再用该 ID 获取完整 TTML，三首均为 HTTP/业务成功。
- 本轮独立脚本用内置 XML 解析工具检查结构，没有引入 AGPL 的官方 TTML npm 包。
- 日文、英文样本还观察到译文与背景人声角色标记；正式实现仍须处理完整时间继承、空格、译文、多声部等语义。
- 带 Origin 的请求观察到响应跨域标头，但这不是浏览器页面中的 CORS 集成测试；Biu 仍应遵守现有固定平台能力/BFF 边界。

## 异常与未收录检查

| 检查 | 实测结果 | 接入时的含义 |
| --- | --- | --- |
| AMLL 不存在的曲目查询 | HTTP/业务 200，items=[] | 可明确显示无匹配 |
| AMLL 不存在的歌词 ID | HTTP/业务 404 | 与服务故障分开 |
| QQ 不匹配的查询 | HTTP 200、网关 code=0，但单项业务 code=2001 | 此码含义未进一步确认；应保留为上游检索异常，勿因数组为空就显示“未收录” |
| 酷狗不存在的曲目查询 | HTTP 200、业务 status=1/error_code=0，lists=[] | 空结果与初次异常空正文分开 |

QQ 返回非零业务码后没有继续向该渠道发起请求。本轮没有主动制造 429/5xx 或探测风控恢复；这些错误处理仍属于接入后的专项验证。固定 QQ SDK 的请求层默认存在重试配置，正式接入应按 Biu 规则关闭相应自动重试；本次探测不运行该 SDK，HTTP helper 没有重试循环。

离线验证另外确认：畸形 XML、含 DTD 的输入、错误 KRC 文件头及损坏压缩体均被拒绝；纯文本不会误标成带时间 LRC。这些是探测器的检查，不是项目现有测试或实际播放器集成通过。

## 已确认的产品决策

**镜台 PV 走独立实现，尽量接近参考视频的真实三维舞台。** 保留空间歌词、前后景深、镜头移动、逐字强调、程序化几何/流体背景；保持当前精美样式可切换，共用 Biu 音频与播放时钟。本轮不移植 Folia/Lumisynth 渲染代码、不联系作者申请模块许可，也不实施 PV。

用户随后明确：**原有精美样式保留，Folia 镜台式三维 PV 与 Lumisynth 式 PV 都纳入目标**。三类外观共用当前音频、歌词、声学对齐和播放时钟；Lumisynth 的具体风格与动态样例继续在[主方案](多源歌词与镜台PV-调研方案.md)中收敛。这项产品范围确认不改变本报告的 9/9 渠道样本口径，也不代表 PV 已实现。

下一步若进入实施：保留来源时间轴与当前录音声学对齐的区别，沿用现有搜索/预览/采用、存储、IPC/BFF/原生网络抽象，分别适配三个来源；原有用户歌词和对齐结果不被静默覆盖。

## 本轮边界

已验证的是本机当前网络下的有限样本 API 取词与基本格式解读。尚未验证 Biu 内部页面、Electron IPC、Web BFF、Android/iOS 的实际集成，也没有重新运行声学对齐、听歌核对时间误差或测试 PV 性能。无需登录的本轮结果不等于所有歌曲、地区或未来版本均具相同条件。代码许可与平台/歌词内容权利依旧分开处理。
