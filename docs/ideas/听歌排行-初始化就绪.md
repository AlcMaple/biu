# 听歌排行：初始化就绪约束

## 2026-10-22 线上验收发现的缺口

登录信息接口正常、页面已显示登录状态，但排行没有发起云端请求，一直停在「尚未读取云端排行」。不是同步服务故障：独立端口的写入、去重、账号隔离均通过。

真实导入链中，平台层经请求模块回到用户 store。用户 store 创建时立即启动 persist hydration，此时平台实现尚未完成初始化，读取 `getStore` 失败。persist 捕获了异常但未触发完成通知，排行等待 `onFinishHydration` 就一直挂着。

## 修正

- 用独立叶子模块 `src/platform/ready.ts` 提供初始化完成信号；平台选择完成后显式释放，用户缓存读取等待该信号。
- 不用固定延时猜初始化完成时间。此次回归中，仅对循环中的平台模块再做动态 import 仍取得未就绪的实现，未解决问题。
- 不把「界面看起来已登录」当成持久化已完成，也不跳过就绪校验把初始空值当用户数据。
- 不改原有用户缓存格式，不迁移旧排行、不改变账号归属。

## 验证与发布处理

此前的排行逻辑测试替换了用户 store，覆盖了人工控制的 hydration 等待，却没有覆盖真实模块循环依赖。新增 `tests/user-hydration.test.ts` 先导入真实平台模块，再验证真实用户 store：有缓存、无缓存均应完成首次 hydration；修复前失败，修复后通过。

首次生产验收发现问题后，先只回退 Web，保留已验证兼容旧客户端的同步服务；修正后重新发布 Web。最终通过 Chrome 实际播放、另一窗口自动更新、公网桌面协议读取和服务器落盘交叉核验。独立端口预检使用内存登录会话与隔离数据，避免与正式进程并发写同一份会话文件。
