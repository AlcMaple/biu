# Biu 响应式实现原型

这是审查用的、可运行的 HTML 实现原型，而不是视觉示意图。它不请求接口，歌曲、封面、播放量、下载项与搜索建议均为模拟数据；但页面层级、控件状态和响应式形态按当前 React 组件逐一对应。

打开 [index.html](./index.html) 即可预览。审查阶段不改动 `src/`、`android/`、`ios/`、线上服务或 `AI_GUIDELINES.md`。

## 文件结构

- `index.html`：页面语义、组件层级和 SVG 图标。
- `styles.css`：桌面、平板、手机断点与所有视觉状态。
- `app.js`：模拟数据、页面状态、抽屉、搜索、播放器和列表交互。

三者均为原型的一部分；后续 React 实施可按同样的结构拆分组件、样式和状态。

## 当前审查标准

通过后，HTML 的每个可见状态应能直接翻译到对应 React 组件，不重新做视觉设计、不额外发明页面形态。

| HTML 原型区域 | 当前 React 对应 | 审查的实际效果 |
| --- | --- | --- |
| 左侧菜单、顶部栏、内容区、底部 88px 播放栏 | `layout/index.tsx`、`layout/side`、`layout/navbar`、`layout/playbar` | 桌面端保持现有 Biu 的页面骨架与控件密度。 |
| 推荐分类、歌曲列头、歌曲行、更多菜单 | `pages/music-recommend`、`components/music-list-item` | 点击分类、播放、更多操作后，列表和播放器同步变化。 |
| 私人 FM、下载记录、搜索结果 | `pages/heartbeat`、`pages/download-list`、`pages/search` | 三种现有页面类型都有可操作的模拟状态。 |
| 搜索输入与建议 | `layout/navbar/search` | 仍是输入框下方的建议层；回车进入搜索结果页，不使用额外全屏搜索页。 |
| 全屏播放器 | `components/full-screen-player`、`mobile.tsx` | 矩形封面、歌词、设置、进度与播放控制，不使用唱片式替代设计。 |

## 响应式断点

| 视口 | 原型形态 | 到 React 的实现意图 |
| --- | --- | --- |
| `≥ 1051px` | 当前桌面壳：200px 侧栏、完整列表列、三栏 88px 播放栏。 | 不改变现有桌面视觉。 |
| `768–1050px` | 平板壳：72px 图标侧栏，歌曲列表和播放栏只隐藏低优先级信息。 | 继续复用同一套 `Layout` / `PlayBar` / `MusicListItem`，只加响应式样式。 |
| `≤ 767px` | 原生移动形态：汉堡菜单抽屉、顶部 `Search`、三列歌曲行、`MobilePlayBar`、底部抽屉队列与移动全屏播放器。 | 让窄 Web 与现有 Capacitor 移动组件采用同一形态；没有底部 Tab，也没有独立路由树。 |

## 已包含的交互

- 推荐分类、歌曲播放、播放/暂停、上一首/下一首、全部播放；手机迷你播放栏顺序为“上一首 / 播放 / 下一首 / 播放顺序 / 播放列表”。
- 搜索建议、回车进入搜索结果、搜索结果播放。
- 私人 FM 的喜欢操作、下载类型筛选、歌曲更多菜单。
- 移动端侧栏抽屉、桌面/移动端播放队列、全屏播放器和播放器设置面板。
- Web 播放栏不展示桌面歌词入口；该能力只保留给 Electron。

## 实施状态

原型获确认后，核心共享布局已按本原型落到 React：窄 Web、平板和桌面间切换不会重挂已加载的歌曲列表。原型未逐一展开的弹窗、本地歌单与设置子页继续复用当前组件行为；需要改变其交互前，应先补充对应原型状态。
