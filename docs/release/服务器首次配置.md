# 服务器首次配置

适用于 Ubuntu / Debian ECS、Apache。已有站点的服务器先检查配置，不要覆盖已有同名文件。以下以 `updates.example.com` + 阿里云服务器 为例，执行前替换域名

## 1. 阿里云控制台

1. ECS → 实例 → 复制公网 IP，填入 `BIU_UPDATE_PUBLISH_HOST`
2. DNS → 将自己的更新域名 A 记录指向该公网 IP
3. ECS 安全组 → 放行 TCP 80、443；TCP 22 仅允许发布者需要访问的来源
4. 通过控制台终端或已有管理员 SSH 登录服务器

下面命令在服务器的管理员终端执行

## 2. 创建上传账户和目录

```bash
sudo apt update
sudo apt install -y openssh-server apache2 certbot python3-certbot-apache
sudo useradd --create-home --shell /usr/sbin/nologin biu-update-publisher
sudo chown root:root /home/biu-update-publisher
sudo chmod 755 /home/biu-update-publisher
sudo install -d -o biu-update-publisher -g biu-update-publisher -m 755 /home/biu-update-publisher/updates
sudo install -d -o root -g root -m 755 /etc/ssh/authorized_keys
sudo nano /etc/ssh/authorized_keys/biu-update-publisher
```

粘贴本机 `biu_update_publisher.pub` 的一整行；Windows 和 Mac 各有一把时粘贴两行。保存后执行：

```bash
sudo chown root:root /etc/ssh/authorized_keys/biu-update-publisher
sudo chmod 644 /etc/ssh/authorized_keys/biu-update-publisher
sudo nano /etc/ssh/sshd_config.d/80-biu-update-publisher.conf
```

填入：

```text
Match User biu-update-publisher
    ChrootDirectory /home/biu-update-publisher
    ForceCommand internal-sftp -d /updates
    AuthorizedKeysFile /etc/ssh/authorized_keys/%u
    AuthenticationMethods publickey
    PubkeyAuthentication yes
    PasswordAuthentication no
    DisableForwarding yes
    PermitTTY no
Match all
```

确认 `/etc/ssh/sshd_config` 包含 `Include /etc/ssh/sshd_config.d/*.conf`，然后检查配置、重新加载：

```bash
sudo /usr/sbin/sshd -t && sudo systemctl reload ssh
sudo /usr/sbin/sshd -T -C user=biu-update-publisher,host=localhost,addr=127.0.0.1 | grep -E '^(chrootdirectory|forcecommand|authorizedkeysfile|authenticationmethods) '
```

预期包含 `chrootdirectory /home/biu-update-publisher`、`forcecommand internal-sftp -d /updates`、`authenticationmethods publickey`。

此时配置对应：

```dotenv
BIU_UPDATE_PUBLISH_USER=biu-update-publisher
BIU_UPDATE_REMOTE_DIR=/updates/
```

## 3. 配置下载域名和 HTTPS

```bash
sudo install -d -o root -g root -m 755 /var/www/biu-update-site
sudo nano /etc/apache2/sites-available/biu-updates.conf
```

粘贴以下配置，把域名换成自己的：

```apache
<VirtualHost *:80>
    ServerName updates.example.com
    DocumentRoot /var/www/biu-update-site

    Alias /updates/ /home/biu-update-publisher/updates/
    <Directory /home/biu-update-publisher/updates/>
        Options -Indexes -ExecCGI
        AllowOverride None
        Require all granted
        <FilesMatch "\.(json|yml)$">
            Header set Cache-Control "no-cache"
        </FilesMatch>
    </Directory>
</VirtualHost>
```

```bash
sudo a2enmod headers ssl
sudo a2ensite biu-updates.conf
sudo apache2ctl configtest && sudo systemctl reload apache2
sudo certbot --apache -d updates.example.com --redirect
```

按 certbot 提示完成证书申请。成功后填写：

```dotenv
BIU_UPDATE_PUBLIC_ORIGIN=https://updates.example.com/updates/
```

## 4. 回到发布电脑测试

将公网 IP 替换为自己的：

Windows CMD：

```bat
sftp -i "%USERPROFILE%\.config\biu\keys\biu_update_publisher" biu-update-publisher@203.0.113.10
```

Mac 终端：

```bash
sftp -i "$HOME/.config/biu/keys/biu_update_publisher" biu-update-publisher@203.0.113.10
```

首次连接核对服务器 SSH 主机指纹。进入后执行：

```text
pwd
ls
bye
```

`pwd` 应显示 `/updates`。完成后回到[发布命令](README.md)，构建并上传自己的安装包。

SSH 私钥和 Windows 更新签名私钥都留在开发电脑，服务器只登记 SSH 公钥。以上为新服务器配置示例，不会自动修改当前项目已部署的服务器。
