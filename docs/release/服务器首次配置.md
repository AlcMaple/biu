# 自建更新站（SFTP + HTTPS）

本页用于首次搭建更新站。已有服务器和发布配置时，直接看[本机发布指南](README.md)

以下示例适用于 Ubuntu / Debian ECS 和 Apache。已有站点先检查配置。执行前把 `updates.example.com` 换成自己的下载域名

## 在本机准备上传密钥

在含 `package.json` 的项目目录中打开终端。已有 SSH 发布密钥时继续使用原密钥。首次生成时，按两次回车接受空口令，然后将私钥做加密备份

**Windows CMD**

```bat
if not exist "%USERPROFILE%\.config\biu\keys" mkdir "%USERPROFILE%\.config\biu\keys"
ssh-keygen -t ed25519 -f "%USERPROFILE%\.config\biu\keys\biu_update_publisher" -C "biu-update-publisher"
type "%USERPROFILE%\.config\biu\keys\biu_update_publisher.pub"
```

**Mac 终端**

```bash
mkdir -p "$HOME/.config/biu/keys"
chmod 700 "$HOME/.config/biu" "$HOME/.config/biu/keys"
ssh-keygen -t ed25519 -f "$HOME/.config/biu/keys/biu_update_publisher" -C "biu-update-publisher"
chmod 600 "$HOME/.config/biu/keys/biu_update_publisher"
cat "$HOME/.config/biu/keys/biu_update_publisher.pub"
```

保留终端输出的 `.pub` 公钥，供下面的上传账户登记。两台电脑各有密钥时登记两行

## 1. 阿里云控制台

1. ECS → 实例 → 复制公网 IP，填入 `BIU_UPDATE_PUBLISH_HOST`
2. DNS → 将自己的更新域名 A 记录指向该公网 IP
3. ECS 安全组 → 放行 TCP 80、443；TCP 22 仅允许发布者需要访问的来源
4. **通过控制台终端或已有管理员 SSH 登录服务器**

**下面命令在服务器的管理员终端执行**

## 2. 创建上传账户和目录

新部署将上传账户的主目录设为 `/srv/biu-update-publisher`，用于存放服务数据。已有部署沿用实际目录，并保持 SSH chroot 与 Apache 路径一致；不要直接套用此处命令迁移目录

```bash
sudo apt update
sudo apt install -y openssh-server apache2 certbot python3-certbot-apache
sudo useradd --create-home --home-dir /srv/biu-update-publisher --shell /usr/sbin/nologin biu-update-publisher
sudo chown root:root /srv/biu-update-publisher
sudo chmod 755 /srv/biu-update-publisher
sudo install -d -o biu-update-publisher -g biu-update-publisher -m 755 /srv/biu-update-publisher/updates
sudo install -d -o root -g root -m 755 /etc/ssh/authorized_keys
sudo nano /etc/ssh/authorized_keys/biu-update-publisher
```

粘贴本机 `biu_update_publisher.pub` 的一整行；Windows 和 Mac 各有一把时粘贴两行。保存后执行：

```bash
sudo chown root:root /etc/ssh/authorized_keys/biu-update-publisher
sudo chmod 644 /etc/ssh/authorized_keys/biu-update-publisher
sudo nano /etc/ssh/sshd_config.d/80-biu-update-publisher.conf
```

填入：

```text
Match User biu-update-publisher
    ChrootDirectory /srv/biu-update-publisher
    ForceCommand internal-sftp -d /updates
    AuthorizedKeysFile /etc/ssh/authorized_keys/%u
    AuthenticationMethods publickey
    PubkeyAuthentication yes
    PasswordAuthentication no
    DisableForwarding yes
    PermitTTY no
Match all
```

确认 `/etc/ssh/sshd_config` 包含 `Include /etc/ssh/sshd_config.d/*.conf`，然后检查配置、重新加载：

```bash
sudo /usr/sbin/sshd -t && sudo systemctl reload ssh
sudo /usr/sbin/sshd -T -C user=biu-update-publisher,host=localhost,addr=127.0.0.1 | grep -E '^(chrootdirectory|forcecommand|authorizedkeysfile|authenticationmethods) '
```

预期包含 `chrootdirectory /srv/biu-update-publisher`、`forcecommand internal-sftp -d /updates`、`authenticationmethods publickey`

此时配置对应：

```dotenv
BIU_UPDATE_PUBLISH_USER=biu-update-publisher
BIU_UPDATE_REMOTE_DIR=/updates/
```

## 3. 配置下载域名和 HTTPS

```bash
sudo install -d -o root -g root -m 755 /var/www/biu-update-site
sudo nano /etc/apache2/sites-available/biu-updates.conf
```

粘贴以下配置，把域名换成自己的：

```apache
<VirtualHost *:80>
    ServerName updates.example.com
    DocumentRoot /var/www/biu-update-site

    Alias /updates/ /srv/biu-update-publisher/updates/
    <Directory /srv/biu-update-publisher/updates/>
        Options -Indexes -ExecCGI
        AllowOverride None
        Require all granted
        <FilesMatch "\.(json|yml)$">
            Header set Cache-Control "no-cache"
        </FilesMatch>
    </Directory>
</VirtualHost>
```

```bash
sudo a2enmod headers ssl
sudo a2ensite biu-updates.conf
sudo apache2ctl configtest && sudo systemctl reload apache2
sudo certbot --apache -d updates.example.com --redirect
```

按 certbot 提示完成证书申请。成功后填写：

```dotenv
BIU_UPDATE_PUBLIC_ORIGIN=https://updates.example.com/updates/
```

## 4. 回到发布电脑测试

将公网 IP 替换为自己的：

Windows CMD：

```bat
sftp -i "%USERPROFILE%\.config\biu\keys\biu_update_publisher" biu-update-publisher@203.0.113.10
```

Mac 终端：

```bash
sftp -i "$HOME/.config/biu/keys/biu_update_publisher" biu-update-publisher@203.0.113.10
```

首次连接核对服务器 SSH 主机指纹。进入后执行：

```text
pwd
ls
bye
```

`pwd` 应显示 `/updates`

## 5. 在本机填写发布配置

回到项目根目录，复制并打开配置文件。已有配置文件时以下命令会直接打开原文件

**Windows CMD**

```bat
if not exist "%USERPROFILE%\.config\biu\production.env" copy dev_tools\release.env.example "%USERPROFILE%\.config\biu\production.env"
notepad "%USERPROFILE%\.config\biu\production.env"
```

**Mac 终端**

```bash
test -f "$HOME/.config/biu/production.env" || cp dev_tools/release.env.example "$HOME/.config/biu/production.env"
chmod 600 "$HOME/.config/biu/production.env"
nano "$HOME/.config/biu/production.env"
```

参照[配置模板](../../dev_tools/release.env.example)，填写服务器公网 IP、上传用户名、远端目录、下载目录的 HTTPS 地址及 SSH 私钥的完整路径。示例中的 `/updates/` 与服务器配置一致。工具会读取这份文件，同名系统环境变量优先。文件内的路径要用实际的完整路径

首次为自己的 Windows 更新站签发版本时，在项目根目录执行以下命令。已经发过版就沿用原签名私钥，换电脑时从备份恢复。只发布 Mac 可直接进入下一节

```bash
node dev_tools/generate-update-signing-key.js
```

把输出的 `keyId` 和 `publicKeyBase64` 分别填入 `shared/update-signing-public-key.js` 的 `UPDATE_SIGNING_KEY_ID` 与 `UPDATE_SIGNING_PUBLIC_KEY_BASE64`，将这个公钥文件提交到自己的 fork。将私钥完整路径填入 `production.env` 的 `BIU_UPDATE_SIGNING_KEY`。私钥默认位于用户目录下的 `.config/biu/update-signing-ed25519.pem`，请在加密位置保存一份备份

## 6. 构建和发布

在项目根目录执行 `pnpm install --frozen-lockfile`。配置原更新地址及密钥后，按[本机发布指南](README.md)使用 `pnpm release:desktop`

打包时会把 `BIU_UPDATE_PUBLIC_ORIGIN` 指定的地址写进客户端。更换发布电脑时沿用原地址和原签名私钥

若上传连接中断，先查看线上更新清单。安装包会先传齐，再逐个替换清单。已有清单使用了本次版本时，下次发布使用更高版本。若发布进程中断后留下空的 `biu-desktop-publish.lock` 目录，先确认各台电脑都已结束发布，再由维护者移除这个空目录
