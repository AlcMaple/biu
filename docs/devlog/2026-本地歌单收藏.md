## 2026-10-24 feat(favorite): 失效自动找同名替换

**效果**：打开本地歌单时，歌单里新发现的失效视频会自动去 B 站找同名视频替换，歌名和时长（相差 15 秒内）都对得上才换，其余不动。原来的「失效内容」按钮改成「失效记录」，每条记录显示「原标题 → 新标题」和状态：已替换（可「换一个」「撤销」）、待处理（可「自己搜索」「删除」）、搜索出错（可「重试」）。「换一个」不会重复给出看过的视频，找不到更多可信的就还原成失效项，交给用户自己搜索。「自己搜索」直接在弹窗里列出搜索结果，点「替换」就顶替对应的失效项，不会留下卡住的待处理记录

**异常边界**：每个失效视频只自动尝试一次，搜索被拦截或失败时立刻停手、记为「搜索出错」并写明原因，只有用户点「重试」才会再搜；失效视频多时排队逐个处理，相邻两次搜索至少间隔 2 秒。对应视频已不在歌单、或失效项自己恢复有效时，记录自动清理。替换目标已在歌单时只移除失效项

## 2026-09-12 perf(favorite): 复用分集信息减少收藏等待

**效果**：播放已经取得视频详情后再收藏，不再重复等待一次分集请求；单集直接展示收藏夹，多集保留选集步骤。播放详情尚未返回时，收藏等待同一个进行中的请求。既有本地条目仍沿用原身份，不进入在线查询。

**关键链路**：视频详情成功 → 按账号与 bvid 保存分集元数据 → 收藏同步读取；未命中时复用进行中请求或发起一次请求 → 返回后进入单集/多集对应步骤。缓存只在页面内存，5 分钟过期、最多 100 份，不缓存完整用户响应、播放地址或失败结果；原详情接口调用仍正常请求，不让其他功能读到缓存的动态信息。

**异常边界**：冷请求仍受上游延迟影响，不承诺固定秒数。业务错误、空分集或网络失败展示“分集信息加载失败，请重试”，不自动重试，也不将未知分集当作单集继续保存。关闭或切换视频后，旧请求迟到不更新当前弹窗。

**验证**：旧弹窗在“播放详情已取得后再收藏”的回归中请求 2 次，修改后总计 1 次（收藏新增请求为 0）；React DOM 验证命中缓存时不显示加载占位、保留多集选择、迟到响应隔离及手动重试。分集缓存、收藏、标签与播放队列共 55 项测试通过，ESLint 和 `pnpm run build:web` 通过。未部署生产，未将测试执行时间当成真实网络耗时提升。

## 2026-09-12 fix(favorite): 统一播放栏与歌单列表的收藏和标签状态

**效果**：播放栏和播放队列的收藏入口优先复用已有本地条目，打开时勾选已有歌单，沿用自定义标题、分集与标签；复制到另一个歌单后再次打开，已有收藏不再被当成新稿件重复添加。

**关键链路**：播放项 → 按来源/类型匹配本地条目（视频优先 bvid + cid，未命中分集再匹配整稿；本地文件与在线音频隔离）→ 与列表共用 `toLocalFavoriteModalData` → 同一个 rid/cid 决定歌单勾选、标签读写与保存。未收藏的在线资源继续原有在线选集流程，不把当前播放 cid 强行写成分集收藏。

**关键修复**：`music-fav-button`、`music-playlist-drawer` 复用 `toPlaybackFavoriteModalData`；星标本地匹配也使用同一规则，避免同视频其他分集误点亮。收藏弹窗从首次打开就依据原条目的 cid 计算标签目标，不依赖上一次关闭弹窗留下的选集状态。

**验证**：旧弹窗在首次打开分集时复现标签缺失；修改后 React DOM 交互验证已有勾选、分集标签、复制、重开与重复提交禁用。收藏身份、分集/来源隔离、既有标签和播放队列回归共 46 项通过，改动文件 ESLint 与 `pnpm run build:web` 通过。本次未修改或自动清理历史重复条目、未改云同步数据协议，未部署到生产。

## 2026-08-07 fix(favorite): 本地歌单分P二次收藏沿用原条目

![本地歌单分P二次收藏数据流：沿用 cid 与用户标题](../devlog-assets/local-favorite-duplicate.svg)

**效果**：

1. 从本地歌单条目的“移动”菜单再次收藏时，直接进入本地歌单选择，不再弹出整稿分P列表；源歌单会按当前条目状态预选。
2. 分P条目使用已保存的 `rid/cid` 做身份匹配，不依赖歌名；复制到另一个本地歌单时保留用户已经修改过的标题、分集序号、分集标题和时长，不再自动追加 `-P32`。
3. 搜索、合集、播放栏等全网收藏入口不带本地来源标记，仍保留原来的 B 站分P选择和在线收藏逻辑。

**关键数据流**：

1. [`src/common/utils/fav.ts`](../../src/common/utils/fav.ts) 的 `toLocalFavoriteModalData` 将本地条目的 `rid/cid/title/page/partTitle` 与 `fromLocalFavorite` 一起传给弹窗；`source` 同时补齐，避免本地文件二次收藏丢失播放来源。
2. [`src/components/favorites-select-modal/index.tsx`](../../src/components/favorites-select-modal/index.tsx) 看到 `fromLocalFavorite` 后跳过 `getWebInterfaceView` 和 B 站收藏夹列表请求，只计算本地歌单的选中状态；`resolveLocalFavoriteSelection` 以原 cid 为 `localRid`，直接使用原标题。
3. [`src/pages/video-collection/local-favorites/index.tsx`](../../src/pages/video-collection/local-favorites/index.tsx) 的“移动”入口统一走上述本地数据转换；目标歌单仍通过 `addOnlineItemToLocalFav` 入库，因此与普通收藏共享持久化、标签和播放量补全路径。

**验证**：新增 [`tests/local-fav-duplicate.test.ts`](../../tests/local-fav-duplicate.test.ts) 覆盖分P身份/标题保留及普通整稿收藏不误带 cid 两条边界。
